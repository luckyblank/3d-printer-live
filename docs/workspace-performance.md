# 工作台实现与性能策略

2026-11-03，按 `designs/printer-workspace-v1.html` 接入真实功能。

## 界面

`workspace-ui.mjs` 移动原控件而不克隆，保留原打印、语音、抓取及保存事件。主窗口使用左侧打印现场、右侧连接/概览/任务标签、覆盖式设置抽屉。中文与英文入口共用布局，独立直播输出不加载工作台导航。正式小窗不显示设计稿的返回按钮或说明角标。

- `demo-panel.mjs` 将演示页整理为测试观众、互动触发、速度与主要操作；头像素材、规则图与下载、演示日志分别折叠。控件及事件仍使用原节点。异步头像图库继续插在 `#avatar-source` 后，规则图下载继续引用原 `.live-rules` 节点。
- `settings-panel.mjs` 只重排打印规则、画面、声音及连接设置的原表单节点，保留值、标识和引擎事件；高级参数与诊断工具按使用频率收纳。
- 「更多」按外观、语言、帮助及程序分组；功能说明与使用教程统一进入 `help.html` 帮助弹窗。帮助页随主窗口主题同步，保留关闭与键盘返回路径。
- 浅色主题覆盖旧控件的内联浅色文字、原生下拉选项、状态文案、禁用项、头像图库和日志，使用主题内的高对比颜色。主题切换采用约 250ms 的颜色过渡；用户启用减少动态效果时取消过渡，不对 3D 画布做截图动画。
- `audio-state.mjs` 将保存的声音意愿与实际播放状态分开。启动未解锁时显示「启用声音」，首次真实点击同步解锁语音与音效；主静音不会被普通点击、聚焦或返回自动取消，异步启用的旧结果不能覆盖后来关闭的决定。音效与播报分别报告可用状态，显式试听不改保存的开关。
- 双语语音引擎等待系统音色就绪，通过播放回调报告状态；未获授权时不积压旧互动，超时或失败提供重试。普通演示重置只取消当前话语并保留原授权，主静音会同时停止与重锁语音。

## 启动与桌面窗口

- 中英文入口在模块加载前用内联关键样式隐藏旧布局，按已保存主题显示启动界面；真实控件完成挂载后，在下一帧统一显示工作台，避免旧版纵向布局闪现。
- 启动期间的模块、必要样式或未处理错误显示失败与重试状态；较慢加载在 10 秒后提供重试入口，继续隐藏尚未挂载完成的旧布局。普通头像或背景图片失败不直接判定整个工作台启动失败。
- 静音偏好在 `giftSpeech` 与语音控件创建完成后恢复，修复保存「声音关闭」后重开程序时提前访问未初始化变量、导致后续挂载中断的问题。
- 主窗口采用无系统标题栏的桌面外观，内置最小化、最大化/还原与关闭操作。最大化遵循当前显示器的工作区，保留任务栏及原生还原边界；工作区或显示器变化时重新适配。
- 最大化按钮读取原生窗口状态，并接收 `workspace-window-state` 事件同步图标、提示及无障碍名称；标题栏双击或原生快捷键引起的最大化/还原也更新为对应图标。
- 桌面入口通过 `desktop=1` 在主窗口初次挂载时预留原生操作按钮的位置；桥接 API 未就绪时按钮禁用，收到 `pywebviewready` 后再启用，避免启动后突然出现按钮并挤动其他操作。
- 独立直播小窗默认置顶，并可在唯一入口「设置 → 小窗」修改；通过 `set_scene_topmost` 立即设置绑定小窗的 `on_top`，重新打开时按已保存偏好传入初值。小窗继续保留系统标题栏及其原生窗口操作，画面内容不增加设计稿的返回按钮或说明文字。
- 小窗视频与交互层使用一致的居中 cover 几何，按比例铺满客户区；窗口比例不同时裁剪超出边缘，避免黑边和拉伸，不改变源视频分辨率。
- 小窗标题栏随工作台深浅主题变化，只修改该窗口的标题栏颜色，不修改 Windows 的系统主题。跨独立 WebView profile 的主题同步使用 `{type:'workspace-theme',theme:'light'|'dark'}` 本机 relay 消息，双端严格校验主题值；沿用既有信令队列与轮询，不在每帧发送主题。该路由包含 Python 服务改动，发布时须重新构建 EXE。

- 小窗设置保存五个独立开关：置顶、队列、互动规则、当前任务与本场统计。默认只显示互动规则，原礼物 PNG 文件保留且在源码与桌面资源中哈希一致；显示数量与头像大小来自实际规则。
- 原礼物 PNG 优先从本地资源路径加载，首次失败后切换到 `scene-gift-icons.mjs` 内相同原文件字节的内联 PNG，按礼物类型记录结果，后续更新不重复请求已失败的路径。内联资源也失败时终止错误处理并隐藏该图像，保留布局，不无限重试、不换成文字或其他图标。
- 「设置 → 小窗」为队列、互动规则、当前任务与本场统计分别提供位置与样式设置：九宫格位置预设、水平/垂直微调、背景不透明度与整体缩放。四个面板使用 `rules`、`queue`、`current`、`stats` 前缀，各自包含 `X`、`Y`、`Opacity`、`Scale`。位置与背景不透明度为 0–100 整数，整体缩放为 60–160 整数，默认背景不透明度 90%、缩放 100%；默认位置依次为规则左下、队列右上、当前任务右下与统计左上。
- 坐标表示面板可移动范围的比例，布局同时考虑面板尺寸与缩放，保持靠边位置在窗口范围内。背景不透明度只调整面板底色；整体缩放让文字、头像、礼物 PNG 与间距等比变化，保持字体与图标的比例，不拉伸图标。
- 业务快照的 `rules` 包含 18 个字段：评论、进场、点赞、关注各自的开关、打印张数和头像大小，加上礼物开关、礼物头像大小与四种礼物数量。此前快照只包含评论与礼物，导致进场等规则已在主端开启却未显示在小窗；现在中英文主端、归一化、中继校验及 viewer 同步四类互动的实际配置。
- 规则卡片在评论打印开启时用「评论 666 → 小图 × 1」举例，结果中的大小和数量随实际配置变化；实际互动仍按已开启的评论打印规则处理收到的评论。规则标题、「评论 666」及输出数量使用随深浅主题变化的局部强调色，其余正文维持主题文本颜色。
- 规则内容、请求缩放或窗口尺寸变化时，viewer 按可用空间适配规则面板；四类互动与四类礼物全部显示时也会在空间不足时自动缩小，以完整显示内容。保存的整体缩放偏好保持不变，例如请求 160% 时仅临时限制实际显示缩放不超过该值。适配由这些变化触发，不在渲染每帧测量面板尺寸。
- 21 项设置统一保存在 `printer-scene-window-settings`，通过完整 `view-settings` 消息同步。旧版五开关或八字段配置自动补齐新增样式默认值，保留已有开关、规则位置与背景不透明度；各面板关闭时禁用其样式控件并保留已存样式。网络层严格要求完整 21 字段，五个开关为布尔值、十二个百分比和四个缩放值为各自范围内的整数，拒绝缺失或额外字段；兼容迁移在前端归一化时完成。该校验随 EXE 更新，发布时须同时构建原生服务与配套前端资源。
- 原生小窗的置顶与标题栏更新统一派发到 WinForms UI 线程。跨线程使用 `BeginInvoke` 和有限等待，不直接从 JS bridge 工作线程写 `TopMost`；标题栏只异步失效，不同步强制绘制。此修复针对小窗启动后无响应的原生路径，浏览器预览及普通 DOM mock 无法覆盖这条路径。
- `scene_window_frame.py` 在小窗的 WinForms UI 所属线程安装仅作用于该 HWND 的窗口 hook，并拒绝跨线程安装或刷新。在系统默认处理 `WM_NCCALCSIZE` 后，仅把客户区左右扩展到窗口边缘，消除两侧原生 frame 占位；顶部标题栏与底部几何保持系统计算结果。原生标题栏按钮、拖动与上下边缘操作保持系统处理；窗口销毁时解除 hook。
- 左右客户区扩展后，WebView2 子窗口会接收边缘指针，单靠父窗口的缩放命中处理无法可靠启动拖拽。viewer 仅在桌面桥接就绪且存在原生 API 时创建左右各 8px 的透明缩放把手；普通浏览器不创建。把手调用仅作用于绑定小窗的 `resize_scene_window('left'|'right')`，在 WinForms UI 线程执行 `ReleaseCapture` 后，以 `PostMessageW` 投递系统非客户区左键消息，避免同步调用阻塞在系统缩放循环中。执行前复核物理左键仍按下，已松开的迟到请求直接忽略；viewer 销毁时移除把手与监听器。
- Windows 支持时，通过 DWM 的 `DWMWA_BORDER_COLOR = DWMWA_COLOR_NONE` 辅助隐藏小窗可见轮廓；左右客户区扩展由上述 frame hook 负责。旧版系统不支持 DWM 属性时安全跳过，标题栏主题仍可独立生效；不修改系统主题或注册表。
- 展示快照最多 2 Hz，按可见内容取值并按 JSON 去重，没有小窗时不读取状态。relay 只保留每个发布者的最新快照，防止重复头像在历史队列堆积。viewer 按卡片和字段更新，进度变化保留原头像与礼物图标节点；信息层不接收鼠标事件。

## 清晰度与性能

- 默认输出 1920×1080，目标 30 FPS；原有竖屏默认升级为 1080×1920。
- 720p/1080p 内部图像至少保持原生 1×。自动策略只能减少超采样，不得把低分辨率放大当作清晰输出。
- 流畅优先持续检测低帧率时，减少 MSAA、实时反射和动态阴影，再将目标帧率降低至 24；不改输出尺寸。手动画质与抗锯齿选择仍保留，关闭流畅优先可恢复所选效果。
- 主离屏渲染缓冲按 HDR、深度与 MSAA 估算，预算 96 MiB。该数字不含输出画布、贴图、反射、视频编码、驱动和 WebView2 自身开销，不能当作整个进程的内存统计。
- 两块反射默认不再单独使用 MSAA，标准反射降低至 512px 宽；软管限制更新频率且复用 position/normal GPU 缓冲。
- 微小螺纹环降低细分；按材质及阴影状态合并静态根零件。当前基准场景 404 个根静态 Mesh 合并为 7 组，不合并运动组、软管或打印成品。
- 背景按需加载，仅保留最近两个房间。头像文件导入先缩至 256px；远程头像 GPU 贴图限制 512px；评分文字保持原有 1024px 标签贴图。
- 最近事件缓存最多 4096；等待任务最多 2048。已接纳任务不会因容量策略删除；新增超量任务会提示。已存在的礼物优先与 FIFO 顺序保持。

## 轻量直播采集集成（2026-11-04）

- 在当前项目的数据桥中接入 DyHub 的轻量 WSS 思路，锁定上游提交 `21251a1150b7320abaac7ab8222cfa6856abcee2`。默认通过本地签名、WebSocket 心跳与 protobuf 解码接收直播事件，继续复用现有打印队列、礼物规则、语音和小窗；没有另建服务项目或引入 DyHub 控制台。
- 登录是本应用临时 WebView2 窗口，在 UI 线程异步读取本应用 profile 中的 Douyin 域 Cookie，当前 Windows 用户 DPAPI 加密保存。成功保存后自动关闭，Node 子进程只通过环境变量接收凭据。普通状态接口、日志、健康检查与分发包不包含 Cookie 值。有效保存态可以直接启动后台采集；失效后提示重新登录。
- 桌面入口固定使用轻量采集，不再自动拉起外部 Chrome 或等待 CDP 9224。原浏览器兼容代码仅保留显式 `PRINTER_COLLECTOR=browser` 的手动诊断入口，桌面按钮不切换到该路径。
